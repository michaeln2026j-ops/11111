# 无人撒料车：整圈横向偏差的可认证上界

本目录把论文的核心方法（共形侵蚀 CE / CE+：用历史作业对"运行级最大偏差"做分布无关的校准）落到模块 A 的循迹上，用来回答一个问题：

> **下一圈作业**里，出料口相对示教路线的**整圈最大**横向偏差，以多大的概率不超过多少厘米？

交付说明里的"直线约 4.3 cm、急转约 2.4 cm"是平均水平，说不清最坏的那一圈会偏多少。本工具给出的则是带统计保证的结论，例如"以 90% 置信度（PAC），每圈最大偏差 ≤ X cm"，可以直接写进验收报告。

## 为什么不能用"平均值 ± 3σ"

一圈约 90 m，路线上有上百个近似独立的截面，整圈最大值一定远大于单点的典型偏差。在合成数据上（`test_feedcar.py`，40 圈）验证的结果：

| 容差带的定义 | 整圈越界的比例（目标 ≤ 10%） |
|---|---|
| 单点 3σ | 28% |
| 单点 95% 分位 | 53% |
| **共形认证（本工具）** | **10%** |

2000–4000 次重复的统计检验（理论值见论文）：

| 版本 | 结果 | 理论值或要求 |
|---|---|---|
| 边际版 | 覆盖率 0.9030 | 理论值 28/31 = 0.9032 |
| PAC 版 | 条件覆盖 ≥ 0.9 的概率为 0.958 | 要求 ≥ 0.9 |

## 文件

| 文件 | 在哪运行 | 作用 |
|---|---|---|
| `ce_core.py` | 工控机 + 笔记本 | 路线读取、带窗口的横向误差投影（与 route_follow 的 `win` 同理，闭环线前后段靠近也不会错配）、按圈切分 |
| `ce_logger.py` | 工控机（ROS Kinetic，Python 2.7） | **只订阅、不发布**，不会影响 route_follow、底盘和停障；每圈写一个 CSV |
| `ce_certify.py` | 笔记本或工控机（Python 2/3 + numpy） | 计算认证上界、留一圈检验、与 3σ 的对比 |
| `test_feedcar.py` | 任意（Python 3） | 离线自测，不需要 ROS |

## 现场操作（在第三章第 6 步之后，与循迹同时运行）

1. **拷到工控机**。不要用 base64，交付说明里提到过会引入乱码；用 scp：

   ```
   scp tools/feedcar/ce_core.py tools/feedcar/ce_logger.py yhs@192.168.1.102:~/
   ```

   拷完后在工控机上检查语法：

   ```
   python -m py_compile ~/ce_core.py ~/ce_logger.py
   ```

2. **先启动循迹**，再在另一个终端启动记录：

   ```
   python ~/route_follow.py _name:=feed_full _loop:=true
   python ~/ce_logger.py _route:=feed_full
   ```

   可选参数：
   - `_off_x:=0.8 _off_y:=0.0`：把测量点从车体中心移到出料口（单位 m，车体坐标）。
   - `_side_deg:=-90 _side_win_deg:=5`：同时记录激光到料槽/墙一侧的最近距离。这是**不依赖定位**的物理量，用来交叉检验定位本身有没有偏差。料槽在车右侧填 −90，左侧填 90。

3. **让车连续跑圈**。每跑完一圈，终端会打印一行，例如 `run 3 complete, max |e| 0.052 m`。第一圈通常从路线中途开始，会被标为 `PARTIAL`，自动不计入。
   - 至少 **9 圈**才能算边际版，**22 圈**才能算 PAC 版。建议 **30–50 圈**。
   - 按 0.2 m/s、一圈约 90 m 计算，每圈约 7–8 分钟，30 圈约 4 小时，可以在日常作业中分几天攒够。
   - 遇障停车、人工接管都没关系，照常记录：它们本来就是真实作业的一部分。
   - 但如果中途改了 route_follow 的参数，要换一个输出目录，参数不同的圈不能混在一起。

4. **出结果**（把 `~/ce_logs/feed_full` 拷回笔记本，或直接在工控机上运行）：

   ```
   python ce_certify.py ~/ce_logs/feed_full --tol 0.10
   ```

   如果只关心贴槽段，可以用 `--s-range 起点:终点` 限定弧长范围（单位 m，可写多段）。

## 结果怎么读

- **certified half-width — PAC**：写进验收报告的数。含义是"以 90% 置信度，下一圈有 ≥ 90% 的概率整圈最大偏差不超过该值"。
- **left / right**：两侧分别给出上界。料槽只在一侧时，看那一侧即可，通常更紧。
- **leave-one-run-out**：留一圈检验的实测越界比例，共形应约等于 eps，3σ 会明显偏高。
- **lidar side distance**：如果它和定位得到的结果差很多，说明定位本身有漂移，需要配合交付说明第六章第 1 项的卷尺闭环法一起看。

## 有效性的前提（如实说明）

- 各圈之间可交换：同一辆车、同一条路线、同一套参数，作业条件（载重、地面湿滑、料量）的波动来自同一个总体。
- 只要某个条件和以前明显不同（例如换了轮胎、改了参数、新铺了地面），就要重新攒圈。
- 偏差 e 是"定位位姿相对示教线"的偏差。真实物理偏差还要加上定位误差，所以要用激光侧距和卷尺法交叉检验。

## 与论文的关系

| 论文中的概念 | 撒料车上对应的量 |
|---|---|
| 运行级精确分数 S = 全程最大偏差，零失误 ⇔ S ≤ λ | 整圈 max\|e\| ≤ 容差 |
| CE+（目标田有历史数据） | 同一条示教线反复跑圈 |
| 第 1 层 Lyapunov 协方差 + 第 2 层 Kac–Rice | 纯跟踪 + kcte 校正的横向误差过程 |
| 第 5 层规模律 √(2 log N) | 新示教一条路线时，按长度预测上界（零数据） |

实车数据可以作为论文的**真实数据验证**：认证上界的实测越界率、与 3σ 的对比，以及不同长度路线之间的规模律。
